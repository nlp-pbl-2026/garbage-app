# 内子町データの再生成と検証

内子町（自治体コード `38422`）の公式「ごみ分別辞典（令和8年5月更新）」と5自治センター管内の「ごみ収集日程表」から、品目検索用CSV、地区台帳、2026年の日付カレンダーを再生成する手順です。

現在はデータ生成基盤までの実装です。Embedding索引は未生成で、`data/regions/catalog.json` へも登録していません。そのため既存自治体の検索・カレンダーには影響せず、内子町はまだアプリの選択肢に表示されません。

## 内子町を選んだ理由

調査レポートで第一段階とされたHTML中心の自治体は対応済みです。次の候補を比較すると、上島町は4地区で構成が単純な一方、現行ページに年度別の実日付カレンダーと詳細な品目辞典がありません。内子町には2026年5月更新の品目辞典と、2026年1月～12月の5管内別実日付表が揃っているため、検索データと収集日を同時に検証できます。

## 対象地区とカレンダー

公式資料は次の5自治センター管内に分かれています。

1. 内子自治センター管内
2. 内子東自治センター管内
3. 大瀬自治センター管内
4. 五十崎自治センター管内
5. 小田自治センター管内

同じ管内でも自治会、道路沿い、生ごみ収集区域、収集場所によって曜日が変わります。そのため、5管内をそのまま5選択肢にせず、公式表に現れる収集ルールの組合せを26地区プロファイルとして台帳化しています。

特に次の条件は別プロファイルまたは確認事項として保持します。

- 内子20区の「元・堀川医院道路向かい収集場所」
- 松尾の生ごみ収集区域内・区域外
- 立川中央の国道56号沿い・沿い以外
- 神南自治会の燃えるごみと資源ごみで異なる地区区分
- 大瀬、和田、川登等の自治会内小地区

燃えるごみ・生ごみは公式の毎週曜日と「収集しない日」から2026年の日付を生成します。資源ごみ・燃えないごみは、公式表の各月に記載された実日付をそのまま抽出します。これにより、5月5日休止後の5月8日・5月9日収集や、池田自治会の1月・8月の1週間ずらしも保持します。

公式カレンダーは「2026年度」ではなく「2026年1月～12月」の暦年資料です。2027年1月以降の日付は生成せず、次年版の公式公開後に別バージョンとして追加します。

## 分別データ

公式PDFの2～13ページにある罫線付き品目表から、品名・種類・備考を876件抽出します。PDFのセル境界で閉じ括弧が分類列へ分離している1件は、規則的に品名へ戻してから分類します。

主な区分は次のとおりです。

- 可燃、不燃、生ごみ、粗大
- 資源かん、資源びん、資源ペットボトル、資源白色トレイ、資源布・古着
- 資源新聞、資源ダンボール、資源紙パック、資源雑誌等
- 廃食油、素材による、家電4品目、禁止

「袋に入らないものは粗大」「一辺20cm以上は不燃」「生ごみ分別収集区域外では可燃」などの条件は、主分類を維持しながら `category_options` に候補を残します。「素材による」は材質を確認するまで自動確定しません。

## Gitで管理するもの

- `data/regions/uchiko/official_rules.json`: 分類、排出方法、回答時の確認事項
- `data/regions/uchiko/sources.json`: 公式原本のURLとSHA-256
- `data/regions/uchiko/calendar_reviews.json`: 26地区の日付・内容ハッシュ
- `data/regions/uchiko/item_reviews.json`: 876品目の件数・分類・内容ハッシュ
- `data/regions/uchiko/registry.json`: 地区台帳とルールプロファイル
- `scripts/uchiko_data.py`: 取得、生成、検証のワークフロー
- `scripts/uchiko_pdf.py`: 品目表とカレンダー表の抽出処理

公式HTML/PDF、生成カレンダー、品目CSV、Embedding索引は `.gitignore` の対象です。内子町サイトの著作権表示に従い、公式原文をリポジトリへ転載しません。

## 再生成手順

### 1. 公式原本を取得

```bash
backend/.venv/bin/python scripts/uchiko_data.py fetch
```

Windowsでは `backend/.venv/Scripts/python.exe` に読み替えます。分別ページ、分別辞典、ごみ出しルール、5管内のカレンダー、著作権ページを `data/regions/uchiko/source/` に保存します。

### 2. 抽出候補を確認

```bash
backend/.venv/bin/python scripts/uchiko_data.py inspect
```

`generated/` にソース、カレンダー、品目のレビュー候補を生成します。候補を公式PDFへ照合してから、`sources.json`、`calendar_reviews.json`、`item_reviews.json` へ反映します。

### 3. 台帳・カレンダー・品目CSVを生成

```bash
backend/.venv/bin/python scripts/uchiko_data.py build
backend/.venv/bin/python scripts/uchiko_data.py verify
```

`build` は原本ハッシュ、レビュー済み日付、レビュー済み品目ハッシュのいずれかが変わると停止します。`verify` は公式原本から再抽出した内容を、地区台帳、生成カレンダー、品目CSVと比較します。

## Embeddingとアプリ登録

Embedding生成はAWS Bedrockへの有償呼び出しなので、このワークフローからは実行しません。品目CSVのレビュー後、明示的な承認を得た場合だけ内子町専用索引を生成します。

索引、manifest、カレンダー、品目CSVがすべて検証できてから、`data/regions/catalog.json` へ `38422` を追加し、Flutter用データを生成します。索引がない現在の段階では登録しません。
