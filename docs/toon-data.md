# 東温市の2026年度データ

東温市（`38215`、版 `toon-2026.1`）の重信・川内地区に対応します。適用期間は **2026-04-01～2027-03-31**。32収集地区・32 PDFは同じ原本からバックエンドとFlutterへ生成します。AWSへの反映、Flutterの配布・実機検証は別作業です。

## 分別と収集方法・時刻

10定期収集区分（燃やす、紙、金属、びん・ガラス、PET、プラ、その他、粗大、蛍光灯・鏡、乾電池）を使います。同日複数区分も保持します。

- 水銀式体温計の分類は共通ですが、重信では乾電池・体温計、川内では蛍光灯・鏡・体温計の日程へ対応します。地域で出し方とカレンダーの対応を切り替え、市専用CSV・索引は共有します。
- **水銀使用の温度計・湿度計、血圧計2行**は辞典の分類「水銀」を保持しますが、どのカレンダー区分に出すか確定できません。専用区分 `mercury_instruments` を収集日未確認とし、検索・カレンダーから市への確認を案内します。この区分の通知・iCal予定は作りません。「予定なし」とは別の状態です。
- **卵パック（プラ製）1行**は原本の分類欄が空欄です。分類を推測で埋めずに索引へ保持し、別の確認済み根拠がなければ判定保留とします。1,280候補すべてを無条件に分類できるという意味ではありません。
- **川内の定期区分、重信の燃やす・紙類は当日午前6～8時**。重信のその他の区分は「各地区で決められた時刻」とされ、個別時刻を確認できません。日付は利用し、搬出時刻は地域で確認と表示します。期限不明の区分では当日朝通知を生成せず、前日通知・終日iCalには時刻未確認の案内を付けます。検索・次回予定は当日の期限内と保証できないため翌日以降を案内します。月間カレンダーには確認済みの当日も表示します。
- 粗大ごみは申込制の戸別収集ではなく、地区の粗大収集日に集積場へ出します。1m程度、標準的な大人2人で運べる大きさ・重さが条件です。確認がなければ質問へ戻します。大量ごみ・処理困難物を定期収集へ含めません。リサイクルセンターは粗大ごみを受け入れません。未登録の品目料金を無料と案内しません。

## 原本との照合

`scripts/toon_pdf.py` はPDFの文字内容、配置・罫線、ベクトル描画色、レンダリング画像を比較します。通常の `get_text()` の一部に古いActualTextが含まれるため、表示文字に対応するglyph traceを使います。

- 全32 PDF・**全11,680日付**の月・日・曜日・セル位置を検査し、区分ラベルと凡例の色を照合します。空欄の日も含みます。
- 描画された収集色の枠からも逆にラベルを確認します。抽出できた文字だけの検査にせず、文字が欠落した色枠をエラーにします。
- 画像をローカルApple VisionでOCRし、区分ラベルを独立に読みます。OCRで読めない小さい文字は、同じPDF内のOCR確認済みラベルの画像形状と比較します。詳細件数は `calendar_reviews.json` に固定します。
- 最下段の日曜で区分が縦に並ぶ場合は、平均的な行高を使わず実際の罫線を使います。逆照合で見つかった27区分の欠落を修正しました。隣り合うセルの文字が連結されて読まれる場合も分離します。
- 白地に白文字として残る古いラベル14か所は、収集色が描かれず画像も空欄であることを確認し、予定から除外します。年末年始の休止表示、祝日、同日複数区分も元の表示に従います。施設開業日から収集予定を作りません。
- 西岡・田窪の同名地区は公式リンクに加え、PDFの通常の4月の燃やすごみ曜日も照合します。この確認から他月の日付を推測していません。
- 辞典は39ページの罫線から1,260行を取得します。分類1,259行のうち1,246行を独立OCRで照合、OCR不読13行を描画した該当行で確認しました。空欄1行も画像で確認しています。`manual_dictionary_reviews.json` に例外を記録します。品目名・注記すべての全文を独立OCRで精査したものではありません。

`calendar_reviews.json` / `item_reviews.json` はレビュー済み要約です。`inspect` の候補を自動で承認しません。原本ハッシュ、件数、抽出・画像照合の結果が変われば停止します。市による校閲や全日付の人手監査を受けたという意味ではありません。

### 無料の取得・生成

リポジトリのルートから実行します。Python3.12、PyMuPDF2.0.0、numpy、macOSのSwift/Apple Visionを使います。`audit-images` はローカルOCRであり、Bedrockは呼びません。

```bash
python3 -m venv backend/.venv  # 新規環境だけ。既存環境を上書きする必要はありません
backend/.venv/bin/python -m pip install -r backend/requirements.txt numpy 'pymupdf==2.0.0' Pillow
backend/.venv/bin/python scripts/toon_data.py fetch
backend/.venv/bin/python scripts/toon_data.py audit-images
backend/.venv/bin/python scripts/toon_data.py build
backend/.venv/bin/python scripts/toon_data.py verify --without-index
```

他OSでは `generated/ocr/` へ共有された132 JSONを配置してから `build` を実行できます。対応する公式資料のハッシュとレビュー要約が一致しないバンドルは使えません。原本が更新され `fetch` が停止したら、古い内容を新しい資料へ自動承認せず、本文・PDFの再レビューが必要です。

### 索引の配置と接続

Git内manifestのSHA-256と一致する共有NPZを `data/regions/toon/knowledge/item_embeddings.npz` へ置きます。**自分で再生成する場合だけ**、別途費用承認とAWS認証の後に実行します。他市の索引は対象に含めません。

```bash
# 有料。必ず事前承認を得る
backend/.venv/bin/python scripts/build_regional_embeddings.py \
  --source data/regions/toon/knowledge/items.csv \
  --output data/regions/toon/knowledge/item_embeddings.npz \
  --municipality 38215 --profile citywide \
  --checkpoint data/regions/toon/generated/titan-checkpoint.jsonl \
  --max-calls 1400 --budget-usd 0.40
```

生成し直した場合は新manifestのハッシュ・件数・モデルも確認します。ベクトルを共有すれば再課金は不要です。

```bash
backend/.venv/bin/python scripts/toon_data.py verify
# カタログ登録済み。activate は新規登録時の検証ゲート用
backend/.venv/bin/python scripts/generate_frontend_data.py
backend/.venv/bin/python -m pytest backend/official_tests/verify_toon_runtime.py -q
cd frontend
flutter pub get
flutter test tool/verify_toon_data_test.dart tool/verify_toon_ui_test.dart
```

標準カタログの他5自治体についても、それぞれのガイドに従いGit管理外データを配置してください。全自治体のFlutterアセット生成・Lambdaパッケージングでは、どれかの必要データが不足すると停止します。バックエンド起動は `backend/` で次を実行し、別ターミナルの `frontend/` から接続します。

```bash
# backend/
USE_BEDROCK_KNOWLEDGE_BASE=false LEXICAL_SEARCH_ENABLED=false \
  .venv/bin/python -m uvicorn app.main:app --host 127.0.0.1 --port 8000
# frontend/（検索は実Bedrockを呼ぶため、利用者側で費用・認証を確認）
flutter run -d chrome --dart-define=API_BASE_URL=http://127.0.0.1:8000
```

`--data-dir <一時ディレクトリ>` を `fetch/audit-images/build/verify` に渡すと、作業データを上書きせず再現検証できます。事前にGit内の東温市JSONと `knowledge/index_manifest.json`、共有NPZだけをコピーしてください。`activate` と併用できません。

## 今回のローカル検証結果

- バックエンド：通常327件＋公式データ統合56件、計383件成功。通常テストは外部API・公式原本に依存しません。Pydantic等の既存非推奨警告4件が残ります。
- Flutter：通常192件と各自治体のデータ・画面検証33件、計225件成功。静的解析は既存のwarning7件・info55件、error0件。今回の追加による診断増加はありません。Webビルド成功。Cupertinoアイコンフォントに関する既存の警告が残ります。
- Lambda用に6自治体・32データファイルをステージングし、同梱先だけを参照する入口・ヘルスチェック・東温市粗大品目API・索引・カレンダーをローカルで確認しました。Linux ARM64バイナリや実AWS実行の検証ではありません。
- 空の一時データディレクトリへ45原本を再取得し、132ページを再描画・再OCRして再生成しました。CSV・台帳・日付・住所候補と、独立生成したFlutterアセットのバイト一致を確認しました。NPZは共有配置であり、有料の再生成はしていません。`reproduction_verification.json` に要約を記録します。
- 最終実検索評価後に、旧 `cutoff_hour` 引数で未確認時刻を上書きできない安全策を追加し、単体テストで確認しました。通常の検索はこの引数を渡さないため評価した経路は変わりませんが、この引数を指定する実API再評価は行っていません。

バックエンドとFlutterの32地区について、収集区分と日付の一致を自動検証しています。ブラウザでの手動通し操作と、スマートフォンでのOS通知・実位置のGPS・共有シートの確認は今回実施していません。AWSデプロイ・アプリ公開も行っていません。
