# ごみサポ

名前が分からないごみも、自然な言葉や画像から分別区分を検索できるFlutterアプリです。

自治体の分別資料をTitan Embeddingによる意味検索で検索し、分類・出し方・次回収集日を回答します。判定に必要な情報が足りない場合は、素材などを確認する追加質問を返します。

現在は松山市、八幡浜市、伊予市、伊方町、新居浜市、大洲市、砥部町、愛南町、鬼北町、松野町、内子町、松前町の12自治体・211選択地区に対応します。各自治体で分別索引と実日付カレンダーを分離し、公式に確認できた期間だけを案内します（[データ配置ガイド](docs/data.md)）。

バックエンドとFlutterには、自治体別の台帳・分別設定・カレンダーを切り替える共通基盤があります。追加した7自治体の品目数・公式期間・再生成方法は[担当7自治体の接続ガイド](docs/assigned-municipalities-completion.md)にまとめています。他市町の追加にも専用の公式データ整備と検証が必要です（[Flutterの自治体データ契約](docs/multi-municipality-flutter.md)）。

伊予市は伊予・双海・中山の3 PDFを16地区の実日付に展開し、搬出期限は8時30分です。平岡・鵜崎の5区分は収集日未確認として案内し、通知・iCalを生成しません。新規cloneでは[伊予市のデータ配置](docs/iyo-data.md)も必要です。

伊方町は伊方・瀬戸・三崎の8 PDFを同じ8収集地区群で利用します。発泡スチロールを含む9定期収集区分は当日8時まで。粗大ごみは申込制とし、収集日を推測せず通知・iCalを生成しません。[対応範囲・公式資料の補正・再生成手順](docs/ikata-data.md)を確認してください。公開APIへの反映は別途必要です。

新居浜市は公式辞典1,349行と15種類の2026年度カレンダーに対応します。市街地・大島は7時30分、別子山は9時まで。大型ごみ・自己搬入は定期予定へ含めません。[対応範囲・再生成・検索評価の制限](docs/niihama-data.md)を確認してください。

大洲市は公式分別辞典632品目と、長浜地域を含む29収集地区の2026年度カレンダーに対応します。定期収集は当日8時まで、粗大ごみは地区別の事前予約制です。指定袋に入るかで分類が変わる品目は、推測せず追加質問で確認します。[公式資料・地区対応・再生成手順](docs/ozu-data.md)を確認してください。

砥部町は公式分別辞典806品目と7収集地区に対応します。定期収集は7時30分までです。現在は公式に照合できた2026年12月6日までのカレンダーだけを収録し、それ以降の日付は通知・iCalにも生成しません。指定袋に入らない大きなごみや20kg以上のごみは、公式案内に従って施設持込等として扱います。[対応範囲と未確認期間](docs/tobe-data.md)を確認してください。

愛南町は公式分別早見表977品目と8ブロックの2026年カレンダーに対応し、定期収集は7時までです。指定袋に収まらない品目や素材で分類が変わる品目は条件を確認し、粗大ごみ・禁止物を通常収集日に変換しません。[公式資料・ブロック・検証内容](docs/ainan-data.md)を確認してください。

鬼北町は公式分別表1,219品目と8収集地区の2026年4月～12月の確認済み日程に対応し、定期収集は8時までです。素材や指定袋の条件に加え、2026年4月開始のきれいなプラスチック拠点回収を通常の可燃・不燃収集と区別します。[対応範囲・例外・再生成手順](docs/kihoku-data.md)を確認してください。

松野町は公式分別表1,434品目と11収集地区の2026年度カレンダーに対応し、定期収集は8時までです。粗大ごみは年2回の回覧案内を確認する運用のため、未確認の収集日を通知・iCalへ追加しません。[地区対応・公式資料・検証内容](docs/matsuno-data.md)を確認してください。

内子町は令和8年5月更新の公式分別辞典876品目と26収集地区の2026年カレンダーに対応します。内子・内子東・大瀬・五十崎は7時30分、小田は8時までです。地区ごとの搬出期限を検索結果、通知、iCalで共通利用します。[地区別搬出期限・再生成手順](docs/uchiko-data.md)を確認してください。

松前町は公式分別辞典1,384品目と松前小学校区・北伊予小学校区の2地区の2026年度カレンダーに対応し、定期収集は7時までです。45L袋に入らない粗大ごみは公式カレンダーの申込期間に従い、未確認の戸別収集日を推測しません。[現行分別ルール・地区対応・検証内容](docs/masaki-data.md)を確認してください。

清水地区を対象にした比較実験では、素のLLMやWeb検索付きLLMより高い精度と短い応答時間が得られました（[実験レポート](docs/experiments.md)）。この結果は全地区・中島地域での検索精度を示すものではありません。

> [!WARNING]
> 収集日は2026年度（2026年4月～2027年3月）の確認済みデータのみ表示します。別年度・未対応自治体には適用しません。中島地域では、根拠や条件が足りない品目の分類は確定せず、追加質問または判定保留にします。

## 使い方

対応済みのAPIへ接続する場合、Flutter側にはAWS認証やローカルBackendの起動は不要です。新規cloneではGit管理外のカレンダーを生成してから起動してください。[セットアップ手順](docs/yawatahama-data.md#新規cloneからの取得再生成)に、松山市・八幡浜市のデータ生成と、ローカルBackendも使う場合の索引配置・起動方法をまとめています。

ハッカソン審査用には、審査担当者から共有されたAPI URLを環境変数に設定し、
プロジェクトルートから次を実行してください。ヘルスチェック、Flutter依存関係の
取得、Chromeでの起動をまとめて実行します。

```bash
export GARBAGE_API_BASE_URL='https://<shared-api-endpoint>'
./scripts/run-demo.sh
```

接続先やデバイスを変える場合は、`GARBAGE_API_BASE_URL`、
`GARBAGE_FLUTTER_DEVICE`を指定できます。
APIの疎通だけを確認する場合は`./scripts/run-demo.sh --check`を使います。

個別に起動する場合は、`frontend/` ディレクトリで次を実行してください。

```bash
export GARBAGE_API_BASE_URL='https://<shared-api-endpoint>'
flutter pub get
flutter run -d chrome \
  --dart-define=API_BASE_URL="${GARBAGE_API_BASE_URL}"
```

初期画面ではログインをスキップして利用できます。

## 主な機能

- 曖昧な表現からのごみ分類
- テキストのみ・画像のみ・画像とテキストを組み合わせた検索
- 対象地域の分別資料を使ったRAG検索
- 判定に必要な追加質問
- 地区ごとの次回収集日の表示
- 検索結果・確信度などのログ分析

## 検索の仕組み（あいまい検索）

品名が分からない曖昧な入力から正解へ到達するため、検索クエリをTitan Text Embeddings V2でベクトル化し、上位候補を判定LLMへ渡します。

1. **クエリ変換**: Amazon Nova Liteがテキストと任意の画像を読み取り、曖昧な入力を検索向けに言い換える。
2. **意味検索**: Titan Text Embeddings V2でクエリをベクトル化し、Lambda同梱の`item_embeddings.npz`から候補を検索する。
3. **判定**: Amazon Nova Liteが画像と検索候補から分類を判定し、必要なら追加質問を返す。

検索画像はJPEG・PNG・GIF・WebPのいずれか1枚、3MBまでです。画像は検索リクエスト内でNova Liteへ渡し、S3や検索ログには保存しません。

両地域で既存の1,756品目のEmbedding索引を検索候補の取得に使います。中島地域では公式カレンダーに明記された79行の分別例・説明を優先し、共通索引から得た候補には中島地域のルールを適用します。松山・北条地域の分類や注意書きをそのまま中島の回答根拠にはしません。候補に入ることと分類を確定できることは別です。既存のAWS環境は、別途更新するまで旧バージョンのままです。

判定は素材・大きさ・製品/容器包装の区別などの分類原則を踏まえ、必要な場合のみ追加質問を1つ返します（`waste_guide_service.py`）。

## 構成

| パス | 内容 |
| --- | --- |
| `frontend/` | Flutterアプリ |
| `backend/` | FastAPI、Titan Embedding検索、分類処理 |
| `backend/evaluation/` | あいまい検索の評価パイプライン（データ生成・採点・比較） |
| `data/` | 自治体ごとの分別資料と地区別の収集カレンダー（[配置ガイド](docs/data.md)） |
| `infra/` | TerraformとAWS構成 |
| `scripts/` | 自治体データの生成・検証、パッケージ作成・AWS関連スクリプト |
| `docs/` | データ配置ガイド・実験レポートなどのドキュメント |

自治体の分別資料から作成したCSVと生成カレンダーはGitに含めていません。松山市の既存Embedding索引は追跡し、それ以外の自治体別NPZ索引はGit管理外で取得・生成します。バックエンドの再構築・再デプロイや精度評価を行う場合は、[`docs/data.md`](docs/data.md)に従って必要なデータを取得・生成してください。

バックエンドの自治体別データ読み込み形式は[複数自治体バックエンドのデータ契約](docs/multi-municipality-backend.md)を参照してください。標準カタログには上記12自治体を登録しています。Git管理外のCSV・NPZ・カレンダーが欠ける環境では、その自治体を別自治体のデータで代用せず、セットアップエラーとして扱います。

## AWS環境の管理

審査用APIは認証不要ですが、API Gatewayで5 req/s、burst 10に制限しています。URLは審査関係者だけに共有し、FlutterへAWS認証情報や分析キーを埋め込まないでください。

```bash
# 構築・更新
./scripts/aws-up.sh

# 削除
./scripts/aws-down.sh
```

`aws-up.sh` はTerraformの適用と比較実験用Knowledge Baseの同期も行います。更新前にLambdaパッケージとTerraform planを確認してください。

AWS構成、費用、権限、ローカルBackendの起動方法は [`infra/README.md`](infra/README.md) を参照してください。

プロンプトと分類処理は `backend/app/services/waste_guide_service.py`、モデルや検索件数などの設定は `backend/app/config.py` にあります。

曖昧検索のデータセット生成と性能評価の手順は [`backend/evaluation/README.md`](backend/evaluation/README.md)、実験設定・結果・誤答分析は [`docs/experiments.md`](docs/experiments.md) を参照してください。
